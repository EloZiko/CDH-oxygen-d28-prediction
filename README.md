# CDH-oxygen-d28-prediction

Prenatal prediction of **oxygen dependency at day 28 of life** in fetuses with
**isolated left-sided congenital diaphragmatic hernia (CDH)**, from four routine
markers of the referral work-up.

This repository contains the final model of the article:

> Vilars P†, El Ouahidi Z†, Russo F, Gay-Cortijo T, El Mazlouzi S, Letourneau A,
> Saada J, Dumery G, Vivanti A, Mahiou E, Benachi A, Leyne E. *Prenatal
> prediction of oxygen dependency at day 28 in isolated left-sided congenital
> diaphragmatic hernia: development and external validation of a
> machine-learning model.* 2026. († equal contribution)

**Web tool:** <https://eloziko.github.io/CDH-oxygen-d28-prediction/>.
The prediction runs in your browser: the values you enter are not sent anywhere.

> [!WARNING]
> **Research use only. This is not a medical device.** The prediction assumes
> survival to day 28 (it is not a risk of death) and reflects current
> management, including FETO when indicated: do not use it to decide on FETO.

## The model

- **Population:** singleton pregnancies with isolated left-sided CDH,
  diagnosed before birth, with a prenatal work-up at a referral centre.
- **Outcome:** supplemental oxygen at day 28 of life, at any flow and by any
  mode.
- **Predictors:** o/e LHR (%), liver herniation (yes/no), deepest amniotic
  fluid pocket (mm) and o/e TFLV (%). At least 2 of the 4 are needed.
- **Algorithm:** CatBoost, 30 trees of depth 2, balanced class weights.
  Missing values are handled by the model (no imputation).
- **Output:** high or low risk. No probability is given: the predicted
  probabilities are poorly calibrated (article, Appendix G).

The hyperparameters, in [`cdh_model.py`](cdh_model.py), were selected by
randomized search with cross-validation on the development cohort
(article, Appendix E). They are fixed here.

| Cohort                      | Fetuses | AUC                        |
| --------------------------- | ------- | -------------------------- |
| Development, Paris-Saclay   | 50      | 0.878 (± 0.076)            |
| External validation, Leuven | 98      | 0.827 (95% CI 0.734–0.908) |

Development: Antoine-Béclère and Kremlin-Bicêtre hospitals (France),
2012–2025, AUC from nested cross-validation (mean ± SD). External validation:
University Hospitals Leuven (Belgium).

## Installation

The project uses [uv](https://docs.astral.sh/uv/). It creates the Python
environment and installs the exact library versions used here, fixed in
`uv.lock`. It also installs Python 3.12 or newer if needed.

```bash
git clone https://github.com/EloZiko/CDH-oxygen-d28-prediction.git
cd CDH-oxygen-d28-prediction
uv sync
```

## Usage

### Web tool

Open [`docs/index.html`](docs/index.html) in a browser. It needs no
installation and works offline.

To publish it online with GitHub Pages: on the GitHub page of the repository,
*Settings → Pages → Build and deployment*, choose *Deploy from a branch*,
branch `main`, folder `/docs`.

### Validate the model on your cohort

Prepare a CSV file in the format described in
[`data/README.md`](data/README.md), then:

```console
$ uv run validate.py data/validation_cohort.csv
```

It prints the AUC with its 95% bootstrap confidence interval, and the accuracy,
sensitivity, specificity and precision. The option `--min-predictors` (0 to 4)
changes the minimum number of predictors a fetus needs (article, Table S1).

The bounds of the confidence interval depend on random resampling: on the
Leuven cohort this script gives 0.737–0.907, where the article reports
0.734–0.908 with the same method and other random draws.

Validation in other centres is welcome: the article calls for an evaluation of
the model in larger cohorts.

### Retrain the model

```console
$ uv run train.py data/development_cohort.csv
```

This writes `models/catboost_o2_d28.cbm` (for Python) and `docs/model.js` (for
the web tool). On the development cohort of the article, it gives exactly the
published model.

## Data

The patient data of the article are not public, for privacy reasons. For
collaboration or research purposes, they can be requested from the
corresponding author. The expected file format is described in
[`data/README.md`](data/README.md).

## Repository structure

```text
cdh_model.py    the model: settings, training, SHAP explanation, web export
train.py        trains the model on the development cohort
validate.py     measures its performance on a cohort
pyproject.toml  project settings: libraries and tests
uv.lock         exact versions of all libraries (generated by uv)
models/         the trained model (CatBoost format)
docs/           the web tool, served by GitHub Pages
tests/          checks that the web tool gives the same results as Python
data/           your CSV files (ignored by git)
```

## Tests

```console
$ uv run pytest
```

The tests run the JavaScript of the web tool and check that it gives exactly
the same class, score and SHAP values as CatBoost in Python.
